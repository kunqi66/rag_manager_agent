## 0. 状态标注约定

| 标记 | 含义 |
|---|---|

## 1. 全局约定（所有表通用，建模前先定）

| 项 | 约定 | 状态 |
|---|---|---|
| 主键 | 一律 `id`，字符串类型（UUID 或雪花），**不依赖自增整数对外暴露** | 🟡 待确认（见 §9） |
| 业务可读编号 | 场景数据里出现 `u_1001`（用户）、数字部门路径 `/1/4/9/`，两者是否统一成一套 ID 策略待定 | 🟡 |
| 创建时间 | `created_at`（DATETIME，UTC 或 Asia/Shanghai 统一） | ✅ 命名一致 |
| 更新时间 | `updated_at`（仅 `kb_document` 明确有） | ✅ |
| 软删除 | `deleted_at`（**仅 `kb_document` 明确有**；用户/角色/部门等是否软删除待确认） | 🟡 |
| 统一响应 | `{code, message, data}`；`code=0` 成功 | 📄 见 `backend/core/response.py` |
| 分页 | `data = {list, total, page, page_size}` | 📄 见 `backend/core/response.py` |
| 字符集 | 全库 `utf8mb4` | ✅ |

## 3. 向量库字段字典（Milvus 2.5，collection `kb_chunk`）

来源 PRD §6.2.2。这是「权限下推到索引」的落点，ACL 是 MySQL 权威权限的**冗余副本**。

| 字段 | 类型 | 说明 | 状态 |
|---|---|---|---|
| id | VARCHAR (PK) | chunk 主键（与 MySQL kb_chunk.id 一致） | ✅ |
| document_id | VARCHAR | 所属知识单元（后置兜底按此复核） | ✅ |
| content | VARCHAR, `enable_analyzer=True`, `analyzer_params={"type":"chinese"}` | 正文，供 BM25 稀疏检索 | ✅ |
| heading_path | VARCHAR | 标题路径 | ✅ |
| dense | FLOAT_VECTOR(768) | BGE 稠密向量，metric COSINE | ✅ |
| sparse | SPARSE_FLOAT_VECTOR | BM25 Function 自动生成，metric BM25 | ✅ |
| acl_global | BOOL | 是否全局公开（冗余） | ✅ |
| acl_departments | ARRAY\<VARCHAR\> | 可见部门 ID 列表（冗余） | ✅ |
| acl_roles | ARRAY\<VARCHAR\> | 可见角色 ID 列表（冗余） | ✅ |
| acl_users | ARRAY\<VARCHAR\> | 可见用户 ID 列表（冗余） | ✅ |

**检索表达式**（动态拼接，§6.2.2）：
```python
expr = ("acl_global == true"
        " or array_contains_any(acl_departments, {depts})"
        " or array_contains_any(acl_roles, {roles})"
        " or array_contains_any(acl_users, ['{uid}'])")
```

**混合检索**（§6.2.2）：`hybrid_search` + `RRFRanker(k=60)`；两个子检索 `limit = top_k * 3`。

> 约束：知识单元 `status != enabled` 不参与检索；权限变更须同步刷新该文档全部 chunk 的 ACL 字段。

## 5. 枚举与状态字典

### 5.1 知识单元生命周期（§6.5，✅）

```
draft → enabled → disabled → enabled（可回切）
draft / enabled / disabled 均可 → 删除（软删除）
```

只有 `enabled` 参与检索。

### 5.2 导入任务状态（✅）

`pending → parsing → embedding → success | failed`

### 5.3 权限实体类型 entity_type（✅）

`global` / `department` / `role` / `user`（`global` 的 entity_id 固定 `*`）

### 5.4 FAQ 与缺口状态（✅）

- faq_candidate.status：`pending` / `published` / `rejected`
- knowledge_gap.status：`open` / `tasked` / `closed`

### 5.5 审计动作类型（🟡 待确认）

PRD 未枚举 `sys_audit_log.action`。建议由各 spec 统一定义，至少覆盖：`login`/`logout`/`user.create`/`user.update`/`user.disable`/`user.grant_role`/`document.import`/`document.permission.update`/`document.delete`/`faq.publish` 等。

### 5.6 功能权限码（✅ §8.1 已定）

| 域 | 权限码 |
|---|---|
| 认证 | 公开（login/refresh）/ 登录（logout/me） |

| 角色 | `org:role:list`、`org:role:*`、`org:role:grant` |

> 🟡 用户 CRUD 细分 `org:user:create/update/delete` 是否独立编码，见用户管理 spec 待确认 8。

## 8. 前端类型映射约定（🟡 拟设计）

| 规则 | 说明 |
|---|---|
| 类型集中 | `frontend/src/types/`，与后端 `backend/schemas/` 一一对应 |
| 命名 | 后端 `UserDetail` → 前端 `interface UserDetail`（同名） |
| 枚举 | 后端 `Literal` → 前端 `type Status = 'draft' \| 'enabled' \| 'disabled'` |
| 分页 | 后端 `{list,total,page,page_size}` → 前端泛型 `Page<T>` |
| 权限码 | 前端 `v-permission` 指令消费；但**后端必须独立校验**（红线 7） |
