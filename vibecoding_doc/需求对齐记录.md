## 2. 方法：grilling 协议

采用 grill-me 技能（Matt Pocock 版）的 grilling 协议对齐需求：

- **设计树**：每个决策向下分出依赖它的子决策，先问「没有前置依赖」的根节点。
- **分轮推进**：每轮问当前「前沿」（前置已定的全部问题），答完再算下一轮前沿。
- **事实 AI 查，决策用户定**：能从代码库 / 环境查到的事实一律由 AI 自查，不占用用户；只有真正的取舍才抛给用户。
- **每题给推荐答案**：AI 在每问附推荐项，用户可采纳、推翻或补自定义（"Other"）。

**实际执行：6 轮、24 个问题。**

## 6. 访谈中浮现的关键风险与问题（AI 主动指出）

1. **越权漏洞**：`AskRequest.user_context` / `SearchRequest.user_context` 由客户端传参，伪造 `role_ids` 即可读到无权文档。→ PRD §11.3 R3，安全红线第 1 条。
2. **MinerU 文档出境合规**：场景一的《高管薪酬与股权激励细则》是敏感件，却要上传第三方站点。→ PRD §11.3 R1（最高优先级风险）。
3. **权限缺失提示是信息侧信道**：报出「存在 N 篇受限文档」会泄漏敏感文档存在这一事实。→ 默认只报数量，`ACL_REVEAL_BLOCKED_TITLES` 默认 `false`。
4. **后置过滤会抽干召回**：Top-K 先召回再过滤会只剩 0-1 条，故采用前置过滤为主 + 后置兜底防越权（D12）。
5. **Milvus 依赖 Docker 而本机没有**：这是「存储选 Milvus」+「本地直连云端」两个决策叠加的必然结果，已入风险清单 R2。
6. **ECS 规格未确认**：按 4C8G 规划（Milvus 单机版自身需 ~4G），低于此会 OOM。→ 待确认项 O2。
