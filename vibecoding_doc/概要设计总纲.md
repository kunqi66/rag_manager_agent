- 单机部署（阿里云 ECS，docker compose 九服务：etcd / minio / milvus / mysql / redis / api / worker / beat / nginx）。

- 中间件对外端口（3306/19530/6379）只为本地直连开发开放，生产靠安全组白名单（PRD R2）。

```

              ▼                         ▼                         ▼
```

### 1.3 分层职责与铁律

| 层 | 职责 | 铁律 |
|---|---|---|
| `api/` | 校验入参、注入 JWT 身份/权限、转发结果 | **禁止业务逻辑与 SQL** |
| `service/` | 组织/认证/审计/看板等横切业务 | 只依赖 engines/clients，不碰 FastAPI |
| `engines/` | import / search / data_mining 核心编排 | **禁止 import FastAPI** |
| `clients/` | 封装 mineru/embedding/llm/milvus/redis | **不泄漏第三方异常**，统一转 `core/exceptions.py` |
| `models/` + `schemas/` | ORM 表 / Pydantic DTO | **跨层只传 DTO，不传裸 dict** |
| `core/` | settings/security/exceptions/response/logging | 全项目横切基础设施 |
| `tasks/` | Celery 任务（worker + beat 共用实例） | 长耗时/定时逻辑放这里 |

## 2. 中间件清单

| 中间件 | 角色 | 关键点 |
|---|---|---|
| MySQL 8.0 | 元数据库、**权威权限**、审计、看板预聚合 | async SQLAlchemy + aiomysql（需 `cryptography`） |
| Milvus 2.5 | 向量库：稠密 BGE + 内置 BM25，RRF 融合，**ACL 标量前置过滤** | standalone，依赖 etcd + MinIO（版本锁死 `RELEASE.2023-03-20T20-16-18Z`） |
| Redis | 三角色：cache(db0) / Celery broker(db1) / result(db2)，另有 JTI 吊销、登录防爆破、FAQ 变更频道 | 生产强制 `--requirepass` |
| Celery | 异步解析、定时挖掘、看板预聚合 | worker + beat；Windows 需 `-P solo`；手动重试要自算 `countdown` |
| Nginx | 反代 + 托管前端 dist | SSE `proxy_buffering off`；上传体积上限 |
| MinerU API | 文档 → Markdown | **异步**、只回 zip URL、下载解压前做路径穿越 + 体积校验（红线 5） |
| BGE 服务 | 文本 → 768 维向量 | 远程 HTTP（PRD D17，GPU 服务器只跑它） |
| DeepSeek | 问答生成 / FAQ 推荐 | `deepseek-chat` |

## 5. 核心流程

### 5.1 认证与身份（P1）

```
登录(username,password)
  → Argon2 校验 → 生成 access(30min) + refresh(7d)
  → access 载荷: {sub, username, depts, roles, perms, exp}
  → Redis 缓存用户有效权限集合(部门含祖先)  ← 关系变更时主动失效

后续请求 → Authorization: Bearer <access>
  → core/deps.get_current_user 解析 JWT（覆盖客户端 user_context，红线 1）
  → require_permission 校验功能权限码（写接口独立校验，红线 7）
```

### 5.2 知识导入（P1）

```
上传文件 → 落 kb_document + kb_import_task(pending)
  → 派发 import.parse_and_index 到 Celery
  → MinerU 异步解析（轮询）→ 下载 zip → 校验路径穿越/体积 → 解压得 Markdown
  → 按标题层级切片(CHUNK_MAX_TOKENS) → BGE 生成 768 维向量
  → 双写：MySQL kb_chunk 存正文；Milvus kb_chunk 存 dense+sparse+ACL 冗余
  → 更新 kb_document.chunk_count + kb_import_task.success
```

### 5.3 权限感知检索问答（P1，核心）

```
用户提问 + session_id
  → JWT 解析出 uid / effective_depts(含祖先) / roles
  → 拼 Milvus 前置过滤表达式：
      acl_global==true or array_contains_any(acl_departments,depts)
        or array_contains_any(acl_roles,roles) or array_contains_any(acl_users,[uid])
  → hybrid_search(稠密 + BM25)，RRFRanker(k=60)，子检索 limit=top_k*3
  → 后置兜底：MySQL 权威权限复核每个 document_id，不一致剔除 + 告警
  → 命中候选 → DeepSeek 生成（SSE 流式：start/delta/citations/blocked/done）
  → 落 qa_session + qa_message + qa_log（含问题向量，供挖掘复用）
```

> 权限模型（PRD §6.1.2）：四维 OR 充分条件，默认无权限行 = 不可检索；部门权限**向下继承**。

### 5.4 FAQ 聚类与缺口闭环（P3）

```
定时 beat(每日 02:00) → mining.mine_faq_clusters
  → 对 qa_log 的问题向量聚类 → 生成 faq_candidate(pending)
  → 治理中心审核 → published 写 faq + 进程内索引 → Redis 发 faq:changed

未命中(qa_log.faq_hit=false 且 top_score 低) → knowledge_gap(open)
  → 治理中心查看 → 补料(type=supplement 导入) → status: tasked→closed
```

### 5.5 运营看板预聚合（P2）

```
定时 beat(每 10 分钟) → stats.aggregate_hourly
  → 汇总 qa_log → stats_hourly/stats_daily（表结构见数据字典 §2.5，待补定义）
  → 看板接口直接读预聚合表
```

## 6. 数据流与中间件协同

| 数据 | 权威源 | 副本/缓存 | 一致性 |
|---|---|---|---|
| 权限（ACL） | MySQL `kb_document_permission` | Milvus `acl_*` 字段冗余 | 权限变更同步刷新该文档全部 chunk |
| 有效部门集合 | MySQL `sys_department.path` | Redis（登录时缓存） | 组织变更主动删缓存 |
| 切片 | MySQL `kb_chunk` | Milvus `kb_chunk`（含向量） | 同 id，双写 |
| FAQ | MySQL `faq` | 进程内 numpy 索引 + Redis 频道 | 发布即刷新 |
| 问答向量 | `qa_log.question_embedding` | — | 落库复用，避免重复调 BGE |

## 7. 开发规范（浓缩，全量见 CLAUDE.md）

**分层铁律**：api 无业务/无 SQL；engines 不 import FastAPI；clients 不泄漏第三方异常；跨层只传 DTO。

**安全红线（违反即严重缺陷）**：
1. 身份从 JWT 解析，覆盖客户端 `user_context`（防越权）。
2. LLM 输出与知识正文渲染前过 DOMPurify。
3. 密码 `pwdlib[argon2]`；JWT 用 `pyjwt`（禁 python-jose）。
4. 未授权内容不返回正文/标题；`ACL_REVEAL_BLOCKED_TITLES` 默认 false。
5. 解 MinerU zip 前路径穿越 + 体积校验。
6. 密钥走环境变量，`.env` 不入库。
7. 每个写接口独立校验功能权限。
8. 数据库参数化，禁 f-string 拼 SQL。

**检索要点**：hybrid_search + RRFRanker(k=60) 且子检索 limit=top_k*3；前置过滤后必须后置兜底；部门权限向下继承；Milvus `content` 开中文 analyzer；SSE 用 fetch+ReadableStream（禁 EventSource）。

**代码规范**：全异步 + 类型注解；统一响应 `{code,message,data}`；分页 `{list,total,page,page_size}`；配置走 `settings.py`（禁 os.getenv）；常量进配置；日志用 logging；中文注释讲「为什么」。
